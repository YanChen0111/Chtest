## 1. 先认识你在测什么

充电桩在行业里常被称为 EVSE。

EVSE 是 Electric Vehicle Supply Equipment，意思是电动汽车供电设备。对 AC 交流充电桩来说，它本身通常不是把交流电变成直流电的“充电器”，真正把 AC 转 DC 给电池充电的是车上的 OBC，也就是车载充电机。AC 充电桩更像一个具备控制、计量、保护、通信和授权能力的安全供电开关。

你可以把 NexBlue 这类 AC 充电桩理解成下面这条链路：

```text
市电输入
  -> 防护/滤波/计量
  -> 主控板
  -> 继电器或接触器
  -> 充电枪/输出端
  -> 车辆

主控板同时连接：
  -> Wi-Fi/BLE/云端/APP
  -> RFID/刷卡模块
  -> 漏电检测
  -> 温度检测
  -> 电压电流采样
  -> 串口日志和 Shell
```

测试工程师要验证的不是“能不能亮灯”这么简单，而是：

- 电是否能安全、正确地送到车端；
- 故障发生时能不能及时断开；
- 设备能不能被正确识别、配置、授权和升级；
- 长时间、反复异常、电网波动、温度变化后是否仍可靠；
- 出问题时日志、错误码、证据是否足够定位问题。

## 2. 必须先建立的安全意识

硬件测试和纯软件测试最大的不同是：错误操作可能伤人、损坏设备，甚至引发火灾。

你需要记住这些底线：

- 不清楚接线含义时，不上电。
- 不确认电源已断开时，不碰裸露端子。
- 不绕过保护器件做“方便测试”。
- 不用手直接接触正在工作的强电部分。
- 不独自执行高压、漏电、过载、高低温等高风险测试。
- 不用普通万用表乱测高能量回路，仪表量程、CAT 等级和表笔都要匹配。
- 测试前确认急停、断路器、隔离电源、灭火器、绝缘手套等安全条件。
- 测试后先断电、放电、确认无电，再拆线。

硬件测试里的“复现问题”也要讲安全边界。比如过载、漏电、欠压过压测试，本质都是制造异常条件，必须使用公司指定设备和测试工装。

## 3. 电学基础

### 3.1 电压、电流、电阻

- 电压 Voltage，单位 V：推动电流流动的“压力”。
- 电流 Current，单位 A：电荷流动的大小。
- 电阻 Resistance，单位 Ohm：阻碍电流通过的能力。

常用公式：

```text
U = I * R
P = U * I
```

其中：

- U 是电压；
- I 是电流；
- R 是电阻；
- P 是功率。

举例：230 V 电压下，设备输出 32 A，理论功率约为：

```text
230 V * 32 A = 7360 W = 7.36 kW
```

三相交流功率通常按下面理解：

```text
P ≈ sqrt(3) * 线电压 * 电流 * 功率因数
```

例如 400 V 三相、16 A，功率大约是 11 kW 级别。

### 3.2 AC 和 DC

- AC：Alternating Current，交流电，家庭和电网常见。
- DC：Direct Current，直流电，电池内部使用。

AC 充电桩输出交流电，车辆内部 OBC 负责转换成直流给电池充电。DC 快充桩则在桩内完成 AC 到 DC 转换，直接给电池提供直流电。

PDF 中的流程更像 AC 充电桩固件和硬件测试流程。

### 3.3 单相和三相

- 单相：常见于家庭用电，通常有 L、N、PE。
- 三相：常见于更大功率场景，通常有 L1、L2、L3、N、PE。

术语：

- L：Live，火线。
- N：Neutral，零线。
- PE：Protective Earth，保护地线。
- L1/L2/L3：三相火线。

PDF 中出现了英国单相、英国三相、老欧洲三相等产品参数，这说明不同地区/型号的硬件接线、电网制式、认证要求和保护逻辑可能不同。

### 3.4 功率和电能

- 功率 kW：此刻消耗或输出的能力。
- 电能 kWh：一段时间内用掉的电量。

测试时常见问题：

- 电流显示是否准确；
- 电量累计是否准确；
- APP/云端/设备本地显示是否一致；
- 断电后电量记录是否丢失；
- OTA 后计量参数是否被错误重置。

### 3.5 频率、谐波和功率因数

- 频率：交流电每秒变化次数，常见为 50 Hz 或 60 Hz。
- 谐波：电流或电压波形畸变产生的额外频率成分。
- 功率因数：有功功率和视在功率的比例。

入门阶段你不需要立刻深入电能质量分析，但要知道：充电桩接入真实电网时，电压、电流和频率并不总是完美稳定。

## 4. 充电桩核心概念

### 4.1 EV、EVSE、OBC

- EV：Electric Vehicle，电动汽车。
- EVSE：Electric Vehicle Supply Equipment，电动汽车供电设备，也就是通常说的充电桩。
- OBC：On-Board Charger，车载充电机，负责把 AC 转成电池需要的 DC。

### 4.2 AC 桩和 DC 桩

AC 桩：

- 结构相对简单；
- 主要负责安全供电、控制导引、授权、计量、保护、联网；
- 车端 OBC 决定实际充电能力上限。

DC 桩：

- 桩内有大功率 AC/DC 模块；
- 直接输出直流给电池；
- 功率更高、成本更高、测试复杂度也更高。

### 4.3 充电接口和控制信号

不同地区常见接口不同，例如 Type 1、Type 2、GB/T、CCS 等。具体 NexBlue 产品使用哪种接口，要以内部规格书为准。

AC 充电桩常见控制信号：

- CP：Control Pilot，控制导引，用于判断车辆连接状态、允许电流等。
- PP：Proximity Pilot，插头接近/线缆容量识别。

测试工程师需要理解：充电桩不是简单地插上就闭合继电器。它通常要先判断插枪、车辆状态、接地、授权、故障状态，再决定是否允许输出。

### 4.4 继电器和接触器

继电器/接触器是控制强电通断的核心器件。

测试关注点：

- 上电前是否保持断开；
- 授权后是否正确吸合；
- 停止充电或故障时是否及时断开；
- 反复通断后是否粘连；
- 异常掉电后恢复状态是否正确。

### 4.5 RCD 和漏电保护

RCD 是 Residual Current Device，剩余电流保护装置。它用于检测火线和零线电流是否不平衡。如果有电流通过人体或其他异常路径流走，就会出现剩余电流，设备应快速断开。

PDF 里提到英国桩需要执行 `cfgset_rcd2` 设置漏电配置，并使用漏电测试工具执行 case。这说明漏电保护是 NexBlue 产品专项测试的重要项。

### 4.6 RFID/刷卡

RFID 是 Radio Frequency Identification，射频识别。刷卡测试验证的是：

- 卡能不能被识别；
- 卡是否已绑定到设备或账号；
- 授权成功后能否启动充电；
- 无效卡是否被拒绝；
- 反复刷卡是否稳定；
- 离线状态下策略是否正确。

### 4.7 OTA

OTA 是 Over-The-Air，远程升级。

PDF 中的 OTA 流程包括：上传 OTA 包、修改 product/firmware/Lowestappversion、上传 JSON、创建 OTA 组、添加 SN、看串口日志、用 `hangall` 查看结果。

硬件测试工程师要理解 OTA 不是单纯的软件功能，它会影响真实设备可靠性：

- 升级中断电会不会变砖；
- 网络波动后能否重试；
- 升级后配置、SN、计量参数是否保留；
- 升级失败是否能回滚或继续运行；
- 大量设备分组升级是否可追踪。

## 5. 充电桩硬件模块和测试关注点

### 5.1 输入保护模块

可能包含断路器、保险丝、浪涌保护、EMI 滤波、压敏电阻等。

关注点：

- 接线是否符合规格；
- 瞬态冲击后设备是否损坏；
- 电网异常是否触发保护；
- 保护器件失效时是否能被发现。

### 5.2 电源模块

电源模块把高压 AC 转成主控板需要的低压 DC，例如 12 V、5 V、3.3 V。

关注点：

- 空载和满载电压是否稳定；
- 上电瞬间是否过冲；
- 低温、高温下是否能启动；
- 反复通断电后是否异常；
- Wi-Fi 发射、继电器吸合时是否掉压。

### 5.3 主控 MCU

PDF 中烧录工具要求选择 ESP32-S3，说明设备主控或通信控制部分使用 ESP32-S3。

关注点：

- 固件能否正确烧录；
- 启动日志是否正常；
- Flash 分区是否正确；
- SN、配置、证书等是否保存；
- 异常复位后是否能恢复；
- Wi-Fi/BLE 是否稳定。

### 5.4 计量模块

计量模块负责测量电压、电流、功率、电量。

关注点：

- 电压电流读数是否准确；
- 小电流、大电流下误差是否可接受；
- 三相计量是否相序正确；
- 电量累计是否断电保存；
- APP/云端/本地日志是否一致。

### 5.5 电流采样和 CT

CT 是 Current Transformer，电流互感器。PDF 中出现 CT 夹子 CX 这样的产品参数，可能与外部电流采样或负载管理有关。

关注点：

- CT 方向是否正确；
- CT 比例参数是否正确；
- 夹错线、反接、松动时系统表现；
- 高低电流下测量是否稳定。

### 5.6 漏电检测模块

关注点：

- AC 漏电是否能检出；
- DC 分量漏电是否能检出；
- 阈值是否符合产品规格；
- 触发后是否切断输出；
- 恢复条件是否正确；
- 错误码和日志是否清楚。

具体阈值和测试波形必须以公司测试计划和适用认证标准为准。

### 5.7 温度检测模块

温度可能来自继电器、端子、线缆、PCB、枪头、环境传感器。

关注点：

- 温度读数是否合理；
- 高温时是否降额或停止输出；
- 传感器断线/短路时是否进入安全状态；
- 高低温箱测试后是否恢复正常。

### 5.8 通信模块

常见通信包括 Wi-Fi、BLE、4G、以太网、RS485、UART。

PDF 中明确出现 Wi-Fi 配网、串口 Shell、APP 连接、云端 OTA。

关注点：

- 首次配网是否成功；
- 密码错误、弱信号、路由器重启时是否有正确提示；
- 反复 Wi-Fi 启停后是否重连；
- 离线期间数据是否缓存；
- 恢复网络后是否补传；
- OTA 过程中断网是否可恢复。

### 5.9 人机交互模块

可能包括 LED、显示屏、蜂鸣器、按键、刷卡区。

关注点：

- 状态显示是否符合定义；
- 故障时提示是否明确；
- 刷卡响应是否及时；
- 反复操作是否卡死；
- 高低温、强光、潮湿环境下是否可用。

### 5.10 结构和环境防护

可能涉及外壳、防水、防尘、防撞、端子固定、线缆应力释放。

关注点：

- IP 防护等级；
- IK 防撞等级；
- 螺丝扭矩；
- 线缆拉力；
- 端子温升；
- 冷凝、潮湿、盐雾等环境影响。

入门阶段先知道这些属于硬件可靠性和结构测试范围，不要把问题全部归为“固件 bug”。

## 6. 把 PDF 里的流程翻译成测试语言

### 6.1 固件烧录

PDF 流程：

1. 使用 `flash_download_tool_3.9.3`。
2. `chiptype` 选择 `ESP32-S3`。
3. 选择对应 FAC 类型固件包。
4. 参数设置为 `0`。
5. 选择设备连接的 COM 串口。
6. 修改 BAUD 波特率。
7. 先点 `ERASE`，再点 `START`。

你要理解的本质：

- 这是把可运行程序写入芯片 Flash；
- `ERASE` 是清掉旧内容；
- `START` 是下载新固件；
- 串口和波特率选错会导致无法烧录；
- 固件包选错可能导致设备无法启动、功能缺失或产品型号错配。

测试证据建议记录：

- 固件包名称和版本；
- 烧录工具版本；
- chiptype；
- COM 口；
- BAUD；
- 擦除和烧录结果截图；
- 首次启动日志。

### 6.2 SN 写入

PDF 流程：

1. 使用 `sscom5.13.1`。
2. 选择串口和波特率。
3. 打开串口。
4. 通过 DTR/RTS 控制设备状态。
5. 使用 `snwrite` 写入 SN。
6. 使用 `snread` 读取确认。

你要理解的本质：

- SN 是设备唯一身份；
- 云端、APP、OTA、售后、日志追踪都依赖 SN；
- SN 写错会导致设备绑定错、OTA 找不到设备、问题无法追踪；
- 写入后必须读回验证。

测试证据建议记录：

- 设备标签 SN；
- 写入命令；
- `snread` 返回值；
- APP/云端显示的 SN；
- 是否和外壳标签、工单、测试记录一致。

### 6.3 Wi-Fi 配网

PDF 中出现命令：

```text
wifiprov ssid password
wifissid
```

含义：

- `wifiprov ssid password`：让设备连接指定 Wi-Fi。
- `wifissid`：查看当前连接的 Wi-Fi 名称。

测试关注点：

- SSID 和密码正确时能否连接；
- 密码错误时是否失败并给出日志；
- 路由器断电后是否重连；
- 信号弱时是否稳定；
- OTA 前是否在线；
- APP 显示是否同步。

### 6.4 电工 APP 验证

PDF 只说“通过电工 APP 连接配置以验证功能正常性”。

你可以把它拆成：

- APP 能否发现设备；
- 是否能绑定设备；
- 是否能读取 SN、版本、网络状态；
- 是否能配置基础参数；
- 是否能启动/停止充电；
- 是否能查看故障和状态；
- 云端和本地状态是否一致。

### 6.5 OTA 测试

PDF 流程包含：

- OA 系统云端上传 OTA 文件；
- 修改 product、firmware、Lowestappversion；
- 上传 JSON；
- 创建 OTA 组；
- 选择 firmware；
- mode 选择根据当前包 OTA；
- 添加要 OTA 的 SN；
- 串口看 OTA 日志；
- `hangallclear` 清除历史 hang；
- `hangall` 查看 OTA 成功情况。

测试关注点：

- 设备是否收到升级任务；
- 下载进度是否正常；
- 下载失败是否重试；
- 校验失败是否拒绝安装；
- 安装后版本是否变化；
- SN 和配置是否保留；
- 升级失败是否可恢复；
- 断电、断网、弱网、连续升级是否稳定。

### 6.6 漏电测试

PDF 中的关键点：

- 前置配置：把设备的两个线接到对应 N 线端；
- 英国桩执行 `cfgset_rcd2`；
- 使用漏电测试工具；
- 配置串口；
- 读取漏电测试计划；
- 选择 case 单步测试；
- 每次测试后设备可能报错，需要断电重启。

你要理解的本质：

- 漏电测试是安全保护测试；
- 测试时故意制造剩余电流；
- 设备应检测到异常并切断输出；
- 测试后设备报错是正常现象，因为保护被触发；
- 每个 case 之间需要恢复到干净状态。

## 7. 你会遇到的主要测试类型

### 7.1 冒烟测试

目标：快速确认设备能启动、能通信、能进入基本业务流程。

典型检查：

- 固件版本正确；
- SN 正确；
- 串口日志正常；
- Wi-Fi 可连接；
- APP 可绑定；
- 继电器未异常吸合；
- 无明显硬件错误码。

### 7.2 功能测试

目标：验证用户可见功能。

典型场景：

- 插枪识别；
- APP 启动/停止；
- 刷卡启动/停止；
- 预约或定时策略；
- 充电状态显示；
- 充电电量统计；
- 离线/在线状态切换。

### 7.3 保护测试

目标：验证异常条件下设备是否进入安全状态。

典型场景：

- 漏电；
- 过流；
- 过载；
- 欠压；
- 过压；
- 过温；
- 接地异常；
- 继电器异常；
- 通信异常；
- 传感器断线或短路。

### 7.4 可靠性测试

目标：验证长时间和反复操作后的稳定性。

PDF 中已有的专项项包括：

- 反复 OTA；
- 反复通断电；
- 反复刷卡；
- 反复连接 Wi-Fi；
- 高温低温测试。

可靠性测试不只看一次能不能成功，更看：

- 100 次、1000 次后是否仍正常；
- 失败率是多少；
- 失败是否集中在某个版本、某个环境、某个硬件批次；
- 失败后是否可恢复；
- 日志是否足够定位。

### 7.5 生产/工厂测试

目标：保证每台出厂设备配置正确、基础硬件正常。

典型内容：

- 烧录 FAC 固件；
- 写入 SN；
- 读取 SN；
- 检查版本；
- 检查通信；
- 检查继电器；
- 检查计量；
- 检查漏电保护；
- 打印或核对标签。

### 7.6 认证前预测试

目标：在正式认证实验室之前发现明显风险。

可能涉及：

- 安规；
- EMC；
- 温升；
- 防水防尘；
- 机械强度；
- 电气间隙和爬电距离；
- 接地连续性；
- 绝缘耐压。

这些通常需要硬件、认证、实验室团队一起执行。

## 9. 测试前检查清单

每次硬件测试前，先确认：

- 测试对象型号、硬件版本、固件版本；
- SN 是否正确；
- 测试环境是单相还是三相；
- 输入电压和电流限制；
- 接线端子是否紧固；
- L/N/PE 或 L1/L2/L3/N/PE 是否接对；
- 测试工具量程和连接方式；
- 是否需要隔离电源、漏保、断路器；
- 是否有急停或快速断电手段；
- 串口日志是否已打开；
- APP/云端账号和 OTA 配置是否准备好；
- 测试结束后的恢复步骤是否明确。

## 11. 常见专项测试拆解

### 11.1 反复 OTA

目标：验证设备在多次远程升级中不会卡死、变砖、丢配置。

重点观察：

- 是否能收到任务；
- 下载是否完整；
- 校验是否通过；
- 安装是否成功；
- 重启后版本是否正确；
- SN 是否保留；
- Wi-Fi 是否保留；
- 历史故障是否清晰；
- 失败后是否可继续升级。

常见问题：

- 固件版本配置错，设备不触发升级；
- product 参数选错，设备不匹配；
- JSON 配置错误；
- SN 没加入 OTA 组；
- 网络不稳定导致下载失败；
- 升级后分区启动失败；
- 断电后停在异常状态。

### 11.2 反复通断电

目标：验证突然断电和恢复后的稳定性。

重点观察：

- 上电是否能启动；
- 启动时间是否异常变长；
- 配置是否丢失；
- 继电器状态是否安全；
- 充电中断电后恢复策略是否正确；
- 日志是否记录断电原因。

常见问题：

- Flash 写入中断导致配置损坏；
- RTC 或状态机恢复异常；
- 继电器上电瞬间误动作；
- Wi-Fi 不重连；
- APP 显示状态不一致。

### 11.3 反复刷卡

目标：验证 RFID 授权稳定性。

重点观察：

- 有效卡是否启动；
- 无效卡是否拒绝；
- 连续刷卡是否去抖；
- 充电中刷卡是否停止或无效，取决于需求；
- 离线时授权策略是否正确；
- 日志是否记录卡号或脱敏标识。

常见问题：

- 卡识别距离不稳定；
- 连续刷卡导致状态机错乱；
- APP/云端授权状态不同步；
- 无效卡被误接受。

### 11.4 反复连接 Wi-Fi

目标：验证网络波动下设备恢复能力。

重点观察：

- Wi-Fi 断开后是否重连；
- 重连时间；
- 云端在线状态；
- OTA 任务是否恢复；
- 离线期间数据是否缓存；
- 日志是否出现内存泄漏、死循环、异常重启。

常见问题：

- DHCP 获取失败；
- 保存了错误 SSID；
- 弱信号下频繁掉线；
- 长时间重连导致设备卡死；
- 云端状态延迟。

### 11.5 漏电测试

目标：验证漏电保护。

重点观察：

- 正常无漏电时不误触发；
- 指定漏电条件下能触发；
- 触发后输出切断；
- APP/日志显示正确故障；
- 断电重启或清故障后恢复策略正确。

常见问题：

- 阈值偏高，危险时不动作；
- 阈值偏低，正常充电误报；
- 触发后继电器未断开；
- 故障码不清楚；
- 不同产品区域配置不一致。

### 11.6 欠压/过压测试

目标：验证电网电压异常保护。

重点观察：

- 低于阈值时是否停止输出；
- 高于阈值时是否停止输出；
- 恢复正常电压后是否自动恢复；
- 是否有防抖时间；
- APP/日志是否显示正确。

常见问题：

- 阈值和规格不一致；
- 电压波动时频繁启停；
- 恢复策略不符合需求；
- 三相某一相异常未检出。

### 11.7 过载测试

目标：验证负载电流超限保护。

重点观察：

- 电流超过限制后是否断开或降额；
- 触发时间是否符合规格；
- 过载恢复策略；
- 继电器和端子温升；
- 日志和 APP 错误显示。

常见问题：

- 采样误差导致误判；
- 高温下过载保护不稳定；
- 继电器长期大电流后粘连；
- 电流限制和 APP 配置不一致。

### 11.8 高低温测试

目标：验证温度环境下设备可靠性。

重点观察：

- 低温是否能启动；
- 高温是否降额或停机；
- 继电器、端子、电源模块温升；
- 显示、刷卡、Wi-Fi 是否受影响；
- 温度恢复后是否正常。

常见问题：

- 低温启动失败；
- 高温 Wi-Fi 掉线；
- 继电器吸合异常；
- 外壳或端子温升超限；
- 传感器漂移。

## 12. 日志怎么看

硬件测试日志通常有几类：

- 启动日志：版本、分区、芯片、复位原因。
- 配置日志：SN、Wi-Fi、product、区域参数。
- 状态机日志：插枪、授权、继电器、充电、停止。
- 保护日志：漏电、过流、过压、欠压、过温。
- 网络日志：Wi-Fi、云端连接、心跳、OTA。
- 异常日志：崩溃、断言、看门狗、hang。

你看日志时不要只搜 `error`。更好的方法是按时间线整理：

```text
设备上电
  -> 版本启动
  -> 读取配置
  -> 连接 Wi-Fi
  -> APP/云端上线
  -> 用户操作
  -> 继电器动作
  -> 故障或成功
  -> 恢复动作
```

PDF 中的 `hangallclear` 和 `hangall` 可以理解为异常记录清理和查看工具。测试前清历史，测试后看新增记录，这样最清楚。

## 13. 硬件测试和软件测试的思维差异

软件测试常问：

- 输入是什么；
- 输出是什么；
- 状态是否正确；
- 接口是否返回预期。

硬件测试还要问：

- 电压电流是否真实正确；
- 波形是否稳定；
- 温度是否安全；
- 接线是否正确；
- 保护是否真的切断；
- 设备是否可恢复；
- 长时间后是否退化；
- 不同批次硬件是否一致；
- 工装和环境是否影响结果。

同一个现象可能有多种原因：

- APP 显示离线，可能是 Wi-Fi 问题、云端问题、SN 错误、证书问题、设备死机、电源掉压。
- OTA 失败，可能是版本配置错、product 错、SN 不在组里、网络差、Flash 分区错、断电、包校验失败。
- 漏电误报，可能是接线问题、传感器问题、阈值配置问题、硬件噪声、测试工装问题。

所以硬件测试要特别重视证据链。

## 14. 硬件相关基本学科知识

硬件测试不是只学一种知识，而是把多个学科的基础串起来。你不需要一开始就成为硬件工程师，但至少要知道问题可能属于哪个领域，这样和研发、硬件、结构、认证、生产同事沟通时不会迷路。

### 14.1 电路基础

这是所有硬件测试的底座。

你需要掌握：

- 电压、电流、电阻、功率、电能；
- 串联、并联；
- 开路、短路、虚接；
- 上拉、下拉；
- 分压；
- 滤波；
- 接地；
- 保险丝、压敏电阻、TVS、热敏电阻等保护器件。

和充电桩测试的关系：

- 欠压/过压测试属于电源输入异常；
- 过载测试属于负载电流超限；
- 漏电测试属于电流路径异常；
- 设备偶发重启可能是电源掉压、接地、干扰或固件异常；
- 端子松动可能造成发热、电流异常、继电器误动作。

测试时常见判断：

- 万用表读不到电压，不一定是没供电，也可能是量程、档位、参考地、表笔位置错；
- 有电压不代表能带载，电源内阻、接触不良、线缆压降都可能导致一带负载就掉压；
- 设备能启动不代表强电路径安全，继电器、接触器、漏电保护还要单独验证。

### 14.2 模拟电路和数字电路

模拟电路处理连续变化的信号，例如电压采样、电流采样、温度采样、漏电采样。

数字电路处理高低电平和逻辑，例如 MCU GPIO、串口、SPI、I2C、继电器控制信号。

测试关注点不同：

- 模拟信号看精度、噪声、漂移、采样稳定性；
- 数字信号看高低电平、时序、通信协议、边沿质量；
- 模拟采样不准可能导致电流、电压、温度、漏电误判；
- 数字控制异常可能导致继电器不动作、刷卡不响应、串口无输出。

入门理解：

```text
模拟问题常表现为：读数飘、误报、阈值边界不稳定。
数字问题常表现为：通信失败、状态不变、设备不响应。
```

### 14.3 电源与功率电子

充电桩里既有强电功率路径，也有弱电控制电源。

你需要知道：

- AC/DC：把交流变成直流；
- DC/DC：把一种直流电压变成另一种直流电压；
- LDO：线性稳压；
- Buck：降压开关电源；
- 纹波：电源上的周期性波动；
- 浪涌：上电或雷击等瞬态冲击；
- 压降：线缆、端子、接触点上因为电流产生的电压损失。

和测试的关系：

- 反复通断电可能暴露电源启动时序问题；
- Wi-Fi 发射瞬间电流变大，可能导致 3.3 V 掉压；
- 继电器吸合瞬间可能拉低 12 V；
- 高温下电源模块能力下降，设备可能更容易重启；
- 过载时线缆和端子温升会增加。

### 14.4 嵌入式系统基础

NexBlue 流程中出现 ESP32-S3、固件烧录、串口 Shell、OTA，这些都属于嵌入式系统。

你需要知道：

- MCU：微控制器，负责运行固件；
- Flash：保存固件、配置、证书、SN；
- RAM：运行时内存；
- Bootloader：启动加载程序；
- 分区：Flash 中不同用途的区域，例如 app、ota、nvs；
- Watchdog：看门狗，设备卡死时触发复位；
- NVS：非易失配置存储，ESP 系列常见概念；
- Reset reason：复位原因，例如上电复位、看门狗复位、异常崩溃。

和测试的关系：

- 烧录失败可能是串口、Boot 模式、Flash、固件包或工具问题；
- OTA 失败可能是分区、下载、校验、重启切换问题；
- 反复通断电可能导致配置写入中断；
- hang 信息可能来自任务阻塞、死循环、内存泄漏或看门狗。

### 14.5 传感器与采样

充电桩会采集很多物理量：

- 电压；
- 电流；
- 温度；
- 漏电流；
- 插枪状态；
- 继电器状态；
- 刷卡信号；
- 门盖或按键信号。

采样链路通常是：

```text
真实物理量
  -> 传感器/互感器/分压电路
  -> 模拟调理
  -> ADC 采样
  -> 固件滤波
  -> 阈值判断
  -> APP/云端/日志显示
```

测试时不要只看最终 APP 数字。一个读数错误可能来自传感器、模拟电路、ADC、固件算法、单位换算、校准参数或显示层。

### 14.6 机械结构与材料

充电桩不是裸板，结构会直接影响可靠性。

你需要知道：

- 外壳材料影响耐候、阻燃、散热；
- 密封圈影响防水；
- 端子和螺丝扭矩影响接触电阻；
- 线缆固定影响拉拽可靠性；
- 外壳空间影响散热；
- 安装方式影响防水和接地。

测试关注点：

- 外壳是否影响刷卡距离；
- 高温时外壳是否变形；
- 雨水或冷凝是否进入；
- 端子松动是否造成发热；
- 枪线弯折是否导致通信或供电异常。

### 14.7 热学基础

所有大电流设备都要关注温度。

你需要知道：

- 温升：工作后比环境温度高多少；
- 热阻：热量从器件传到环境的难易程度；
- 热保护：温度过高时降额或关断；
- 热惯性：温度变化不是瞬间完成的，有滞后。

和测试的关系：

- 过载不一定马上坏，可能先表现为温升超限；
- 高温箱测试会让电源、继电器、端子更接近极限；
- 低温可能导致继电器动作、电容启动、塑料结构表现变化；
- 温度传感器位置不合理时，APP 显示温度可能不能代表热点温度。

### 14.8 EMC、EMI 和 ESD

这些属于电磁兼容相关知识。

- EMC：Electromagnetic Compatibility，电磁兼容，设备既不严重干扰别人，也能抵抗外部干扰。
- EMI：Electromagnetic Interference，电磁干扰。
- ESD：Electrostatic Discharge，静电放电。

和充电桩的关系：

- 继电器切换、大电流、电源模块都可能产生干扰；
- Wi-Fi/BLE/RFID 属于无线通信，容易受结构、接地、干扰影响；
- 静电可能导致按键、刷卡、通信、MCU 异常；
- 强干扰环境下设备可能重启、串口乱码、误报漏电。

入门阶段你不用设计 EMC，但要会描述：

- 干扰发生时设备在做什么；
- 是否伴随继电器动作、负载变化、刷卡、Wi-Fi 发送；
- 是否可复现；
- 复位原因是什么；
- 是否只有某个批次或某个安装环境出现。

### 14.9 安规与认证基础

安规关注的是“设备即使故障，也不能轻易伤人或起火”。

常见概念：

- 绝缘；
- 耐压；
- 接地连续性；
- 漏电流；
- 爬电距离；
- 电气间隙；
- 温升；
- 阻燃；
- 防水防尘；
- 防触电。

测试工程师要知道：

- 安规测试通常不能随意改条件；
- 认证测试失败不一定是固件问题，也可能是结构、材料、PCB、接地、线缆问题；
- 保护类测试一定要保留证据，包括仪器读数、动作时间、错误码和恢复行为。

### 14.10 可靠性与失效分析

可靠性关注“能不能长期稳定工作”。

常见概念：

- 老化：长时间运行暴露早期问题；
- 应力：高温、低温、湿度、电压波动、机械振动等外部压力；
- 失效率：单位时间或次数内的失败比例；
- 批次差异：不同生产批次表现不同；
- 退化：器件性能随时间变差；
- 根因：真正导致问题的底层原因。

和 PDF 中专项测试的关系：

- 反复 OTA：软件升级可靠性；
- 反复通断电：电源和配置保存可靠性；
- 反复刷卡：RFID 和状态机可靠性；
- 反复 Wi-Fi：网络恢复可靠性；
- 高低温：环境可靠性。

### 14.11 生产制造基础

很多硬件问题来自生产过程。

你需要知道：

- SMT：贴片生产；
- DIP：插件生产；
- 焊点虚焊、连锡、少锡；
- 端子压接；
- 螺丝扭矩；
- 标签和 SN 绑定；
- 工厂测试；
- 校准；
- 批次追踪。

测试时如果发现“同一版本大部分正常，少数设备异常”，要怀疑：

- 个体硬件损坏；
- 焊接问题；
- 端子装配问题；
- SN 或配置写错；
- 校准数据缺失；
- 批次物料差异。

## 15. 通讯知识基础

充电桩测试里，很多问题表面上是“APP 不显示”“OTA 失败”“串口没反应”“Wi-Fi 掉线”，本质都是通信问题。通信知识可以分成三层理解：设备内部通信、设备到手机/云端通信、充电协议通信。

### 15.1 通信的基本模型

所有通信都可以先用这个模型理解：

```text
发送方
  -> 编码/打包
  -> 传输介质
  -> 解码/解析
  -> 接收方
  -> 应答或超时
```

测试时常问：

- 谁发给谁；
- 发的是什么；
- 通过什么通道发；
- 有没有收到；
- 收到后有没有解析成功；
- 失败有没有重试；
- 超时多久；
- 日志里有没有错误码。

### 15.2 串口 UART

PDF 中大量使用串口工具，所以 UART 是你最先要掌握的通信知识。

UART 常见参数：

- COM 口：电脑识别到的串口号；
- Baud rate：波特率，例如 115200；
- Data bits：数据位，常见 8；
- Stop bits：停止位，常见 1；
- Parity：校验位，常见 None；
- TX：发送；
- RX：接收；
- GND：地。

常见问题：

- COM 口选错；
- 波特率错导致乱码；
- TX/RX 接反；
- 没有共地；
- 串口被其他工具占用；
- DTR/RTS 状态导致设备复位或进入下载模式；
- 回车换行设置错误导致 Shell 命令不执行。

测试建议：

- 先保存一份正常启动日志；
- 每次测试前确认 COM 口和波特率；
- 输入 Shell 命令后记录完整回显；
- 串口日志要带时间戳；
- 重要测试前先执行清理命令，例如 `hangallclear`。

### 15.3 TTL、RS232、RS485

这些都是串口相关，但电气层不同。

- TTL UART：MCU 常用，电平可能是 3.3 V 或 5 V。
- RS232：传统 PC 串口标准，电平范围和 TTL 不同，不能直接乱接。
- RS485：差分总线，抗干扰强，适合长距离、多设备。

入门记法：

```text
UART 是通信方式。
TTL/RS232/RS485 是电气连接方式。
同样叫串口，不代表可以直接互接。
```

充电桩场景中，RS485 常用于电表、外部模块或工业通信，但 NexBlue 是否使用要以内部分解图和原理图为准。

### 15.4 I2C 和 SPI

I2C 和 SPI 常用于板内芯片通信。

I2C 特点：

- 两根主要信号线：SCL、SDA；
- 一个总线上可挂多个设备；
- 常见于传感器、EEPROM、低速外设。

SPI 特点：

- 常见信号：SCLK、MOSI、MISO、CS；
- 速度通常比 I2C 快；
- 常见于 Flash、显示屏、射频模块等。

测试工程师一般不直接操作 I2C/SPI，但要知道：

- 如果温度、电流、刷卡模块读不到，可能是板内通信异常；
- 这类问题通常需要研发用逻辑分析仪或示波器定位；
- 你的测试证据应包含故障日志、复现步骤、是否重启恢复。

### 15.5 CAN 和 Modbus

CAN 是 Controller Area Network，常见于汽车和工业控制。Modbus 是工业通信协议，常见于电表、控制器、能源设备。

它们是否用于 NexBlue 产品，要看内部设计。

你需要知道的测试点：

- 地址配置是否正确；
- 波特率是否匹配；
- 终端电阻是否正确；
- 主从关系是否正确；
- 超时、重试、异常码是否处理；
- 总线干扰或断线后是否恢复。

### 15.6 Wi-Fi

PDF 中有反复 Wi-Fi 连接测试，Wi-Fi 是充电桩联网和 OTA 的关键。

基本概念：

- SSID：Wi-Fi 名称；
- Password：Wi-Fi 密码；
- RSSI：信号强度，通常是负数，越接近 0 越强；
- DHCP：自动获取 IP；
- Gateway：网关；
- DNS：域名解析；
- 2.4 GHz/5 GHz：Wi-Fi 频段。

很多 IoT 设备只支持 2.4 GHz，具体 NexBlue 产品能力以规格书为准。

常见问题：

- 密码错误；
- 路由器只开 5 GHz；
- 信号弱；
- DHCP 分配失败；
- DNS 解析失败；
- 路由器重启后设备不重连；
- OTA 下载时网络断开；
- 同一 SSID 下漫游异常。

测试建议：

- 记录 SSID、路由器型号、频段、距离；
- 记录 RSSI；
- 区分“连上路由器”和“连上云端”；
- 断网测试时分别测试断路由器、断外网、弱信号；
- OTA 测试时保留下载日志和重试日志。

### 15.7 BLE 和 APP 配网

BLE 是 Bluetooth Low Energy，低功耗蓝牙。很多 IoT 设备用 BLE 做首次配网：手机先通过蓝牙把 Wi-Fi 名称和密码发给设备，然后设备再连接 Wi-Fi。

测试关注点：

- 手机能否扫描到设备；
- 蓝牙权限是否开启；
- 设备是否处于配网模式；
- 配网超时是否提示；
- Wi-Fi 密码错误是否能反馈；
- 配网成功后 BLE 是否退出或保持；
- 不同手机系统版本是否表现一致。

如果 APP 配网失败，要区分：

```text
手机没有发现设备
手机发现设备但连接失败
BLE 发送 Wi-Fi 信息失败
设备收到信息但 Wi-Fi 连接失败
Wi-Fi 连接成功但云端绑定失败
```

### 15.8 以太网、4G 和其他联网方式

部分充电桩可能支持有线网或蜂窝网络。是否适用于 NexBlue 产品，以内部规格为准。

以太网测试关注：

- 网线和接口；
- DHCP/静态 IP；
- 网关；
- DNS；
- 断线重连；
- MAC 地址。

4G 测试关注：

- SIM 卡；
- APN；
- 信号强度；
- 运营商网络；
- 流量；
- 弱网；
- 掉线重连。

### 15.9 TCP/IP 基础

设备连接云端时通常离不开 TCP/IP。

你需要知道：

- IP：设备网络地址；
- Port：端口；
- TCP：可靠连接，适合大多数业务通信；
- UDP：无连接，开销小但不保证送达；
- DNS：把域名解析成 IP；
- TLS：加密通信；
- 心跳：设备定期告诉云端“我还在线”；
- 超时：规定时间内没收到响应就认为失败；
- 重试：失败后再次发送。

测试时常见问题：

- 设备拿到 IP 但 DNS 失败；
- DNS 成功但 TCP 连接失败；
- TCP 成功但 TLS 握手失败；
- 云端连接成功但鉴权失败；
- 心跳中断导致 APP 显示离线；
- 本地日志显示在线但云端状态延迟。

### 15.10 HTTP、MQTT、WebSocket

IoT 设备常见应用层协议：

- HTTP：请求/响应模式，常用于接口调用、文件下载；
- MQTT：发布/订阅模式，IoT 常用，适合设备和云端消息；
- WebSocket：长连接双向通信。

NexBlue 具体使用哪种协议要看内部设计。测试工程师的核心不是背协议细节，而是理解：

- 设备上线需要鉴权；
- 云端下发命令需要设备在线；
- 设备上报状态可能有延迟；
- OTA 下载可能走 HTTP 或其他文件通道；
- 弱网下需要重试和断点恢复机制。

### 15.11 OCPP

OCPP 是 Open Charge Point Protocol，充电桩和充电管理平台之间的开放协议。很多商用充电桩会支持 OCPP，用于远程管理、启动停止、计费、状态上报、固件升级等。

本文不能断定 NexBlue 当前产品是否使用 OCPP；如果内部需求提到 OCPP，你需要重点学习：

- BootNotification：桩启动注册；
- Heartbeat：心跳；
- StatusNotification：状态上报；
- Authorize：授权；
- StartTransaction/StopTransaction：交易开始/结束；
- MeterValues：电表数据；
- FirmwareStatusNotification：固件升级状态；
- Reset：远程重启。

测试关注点：

- 平台是否能识别设备；
- 设备状态是否准确；
- 远程启动/停止是否生效；
- 交易数据是否完整；
- 网络断开后交易数据是否补传；
- OTA 状态是否和设备日志一致。

### 15.12 充电控制通信：CP/PP/PWM

AC 充电桩和车辆之间通常通过 CP/PP 等信号完成连接状态和允许电流协商。

入门理解：

- PP 用于识别插头/线缆能力；
- CP 用于告诉车辆充电状态和可用电流；
- PWM 占空比可用于表达允许电流；
- 车辆状态变化会影响桩是否闭合继电器。

测试关注点：

- 未插枪时不能输出；
- 插枪但未授权时不能输出；
- 授权后状态正确才允许输出；
- 停止充电后应断开输出；
- 异常状态下应进入保护。

如果测试中没有真实车辆，可能会用车辆模拟器或充电测试工装。

### 15.13 通信问题排查路径

当你遇到“通信失败”，按这个顺序查：

1. 物理连接：线是否插好，TX/RX 是否接对，网线/天线/卡是否正常。
2. 参数配置：波特率、SSID、密码、IP、端口、product、SN 是否正确。
3. 本地状态：设备是否启动、是否有日志、是否进入正确模式。
4. 链路状态：是否连接 Wi-Fi，是否拿到 IP，是否能连云端。
5. 鉴权状态：证书、Token、SN、账号绑定是否正确。
6. 协议状态：命令格式、JSON、版本、字段是否匹配。
7. 超时重试：失败后是否重试，重试次数和间隔是否合理。
8. 恢复能力：断电、断网、重启后是否恢复。

### 15.14 通信测试要保留的证据

建议保留：

- 设备 SN；
- 固件版本；
- APP 版本；
- 云端环境；
- Wi-Fi SSID 和信号强度；
- 串口完整日志；
- APP 截图；
- 云端后台截图；
- OTA 配置截图；
- 失败时间点；
- 路由器或网络环境说明；
- 是否可复现；
- 是否重启/重新配网后恢复。

## 17. 建议的 30 天学习路线

### 第 2 周：理解功能链路

目标：

- 理解 APP、设备、云端、SN 的关系；
- 理解刷卡、配网、OTA 的基本流程；
- 能判断常见失败是配置问题、网络问题还是设备问题。

练习：

- 做一次反复刷卡测试；
- 做一次 Wi-Fi 断开重连测试；
- 做一次 OTA 正常升级；
- 写一份完整 bug 报告。

### 第 3 周：理解保护类测试

目标：

- 理解漏电、欠压、过压、过载、过温；
- 知道这些测试为什么危险；
- 能读懂测试计划和测试仪器输出；
- 能区分“保护动作正确”和“设备异常失败”。

练习：

- 跟随资深同事完成一次漏电测试观察；
- 整理漏电测试中的前置条件、操作、预期、恢复；
- 学会记录测试仪器读数和设备日志对应关系。

### 第 4 周：形成测试分析能力

目标：

- 能设计简单的可靠性测试；
- 能对失败做初步归因；
- 能把硬件环境、固件版本、日志和结果串起来；
- 能提出缺少的测试证据。

练习：

- 完成一次反复通断电测试记录；
- 完成一次反复 OTA 测试记录；
- 整理 5 个常见故障的排查路径；
- 建立自己的术语表和命令速查表。

## 18. 给零基础测试工程师的工作方法

### 16.1 每次只改一个变量

硬件测试环境复杂，不要同时换固件、换桩、换线、换路由器、换 APP 版本。否则失败后无法判断原因。

### 16.2 先确认测试环境，再判断产品缺陷

很多问题来自环境：

- 串口选错；
- 波特率错；
- SN 写错；
- Wi-Fi 密码错；
- OTA 组没加 SN；
- product 参数选错；
- 线接错；
- 工装配置错。

先排除这些，再提缺陷。

### 16.3 记录版本

硬件测试必须记录：

- 硬件版本；
- 固件版本；
- APP 版本；
- 云端环境；
- 测试工具版本；
- 测试计划版本。

版本不清楚的 bug，定位价值会大幅下降。

### 16.4 建立自己的命令速查表

从 PDF 中可先整理：

```text
snwrite              写入 SN
snread               读取 SN
wifiprov ssid pwd    连接 Wi-Fi
wifissid             查看当前 Wi-Fi
hangallclear         清除 hang 信息
hangall              查看 hang 信息
cfgset_rcd2          设置漏电检测配置，PDF 中说明英国桩使用
```

具体命令格式、参数、返回值，以内部 Shell 指令文档为准。

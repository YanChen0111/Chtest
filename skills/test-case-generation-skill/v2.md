# Skill: test-case-generation-skill v2

## Applies To

- CaseGenerationAgent

## Methodology

- Claim-first test design: select an immutable source claim before designing a scenario.
- Equivalence partitioning and boundary analysis only when a cited claim supports the partition or boundary.
- State, negative, and risk-based testing only when requirement or risk evidence supports the behavior.
- Per-case traceability from source claim to steps and observable expected results.

## Input Contract

Accept an immutable `requirement_claim_snapshot`, requirement review, reviewed
risks, optional approved knowledge evidence, target test types, and the
acknowledged decision-table dimensions.

## Output Contract

Return candidate cases only. Every candidate includes `coverage_claims` with
existing claim ids and supporting excerpts, plus requirement/risk references,
steps, expected results, coverage dimensions, and generation reason.

## Quality Gates

- Every candidate cites at least one existing immutable requirement, document, or risk claim.
- Every citation excerpt overlaps its source claim and the candidate tests the cited behavior.
- Risk citations include the matching risk id in `risk_refs`.
- Knowledge citations include the matching persisted item in `source_knowledge_evidence`.
- Every candidate has executable steps and observable expected results.
- Unsupported negative, boundary, permission, retry, and state scenarios are omitted instead of invented.
- Generated candidates remain in review state and never become official TestCase records automatically.

## Forbidden Actions

- Do not invent claim ids or rewrite source claims.
- Do not infer unstated business rules from a generic testing checklist.
- Do not use one grounded candidate to justify an unrelated candidate in the same batch.
- Do not create official TestCase records or bypass CaseReviewSession.

## Tool Permissions

- No execution tools.
- KnowledgeAdapter.search_context is optional only when enabled by the workflow.

# Skill: automation-plan-skill v1

## Applies To

- AutomationPlanAgent

## Methodology

- Start from one approved TestCase and preserve its traceability.
- Cross-check the TestCase against requirement evidence and requirement review evidence.
- Use provided knowledge evidence and context artifacts to refine data, fixture, selector, and dependency assumptions.
- Decompose the behavior into reviewable automation steps before any code generation.
- Keep the plan small enough for a reviewer to approve or reject.

## Input Contract

Accept one approved TestCase, source candidate id, source requirement id,
requirement review id, target framework, optional repository context, optional
context artifact manifest entries, and optional deterministic knowledge
evidence.

## Output Contract

Return one AutomationPlan with title, source traceability, target framework,
execution steps, test data, dependency notes, risk notes, used context artifact
ids, and copied knowledge evidence references.

## Quality Gates

- Plan must identify an approved TestCase as its source.
- Plan must combine TestCase intent with requirement evidence, requirement review evidence, and supplied knowledge evidence.
- Plan must include target framework, execution steps, test data, dependency notes, and risk notes.
- Plan must require approval before AutomationDraft or code generation.
- Plan must not contain executable automation code or arbitrary shell commands.

## Forbidden Actions

- Do not generate or apply automation code.
- Do not create a plan from an unapproved TestCase.
- Do not ignore requirement, review, context, or knowledge evidence that changes the plan.
- Do not execute arbitrary commands or embed shell strings for execution.
- Do not mark the plan approved.

## Tool Permissions

- No execution tools during plan generation.
- Read only the evidence supplied in the prompt input.
- TestRunnerTool and shell command tools are forbidden until a later approved workflow step.
